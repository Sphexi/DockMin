How a restore runs

  1. Take this instance offline.
  2. Upload the archive and review what it holds and what it replaces.
  3. Enter the encryption key the archive was made with. Nothing changes before the key is accepted.
  4. dockmin verifies the archive, stages its database, migrates it and checks it, then replaces this instance's data and restarts on it.

While the instance is offline

  • Every request that changes something is refused with status 503. Pages can still be read, and signing in and out still works.
  • Scheduled jobs stop, and a run in progress is interrupted.
  • Backup downloads are refused.
  • The instance accepts changes again when the restore is cancelled, when 15 minutes pass without a restore request before the key is confirmed, and when the application stops.

What a restore changes

  • Users, environments, stacks, credentials, rules and the activity log are replaced by the archive's. Changes made after the backup are lost.
  • Every session ends, yours included. Sign in again with an administrator account from the archive. Your user name must match an enabled administrator in the archive.
  • The data being replaced is moved aside and kept. dockmin never deletes it.
